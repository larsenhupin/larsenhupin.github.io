Serial Graph in C++ using Dear ImGUI on Linux

Sep 28, 2025


Graphics

When deciding to create a graphical user interface (GUI), there is many options to choose from. Before graphics card, people would write pixels data directly into a backbuffer and the CPU would be responsible to render it. This is a raw technique that worked for a very long time (and still does), but compared to the modern approach it’s consider slow.

In the late 90s, graphics cards started to appear more widely on the market and vendors would ship them with graphics API drivers like OpenGL. More complex graphics, like 3D, became more widely available.

Writing an OpenGL/DirectX renderer means that you call specific GPU functions to draw shapes and color on the screen.

  • CPU rendering - Write pixel data on a back buffer
  • GPU rendering - Call the graphic card functions to draw shape and color

Both are low-level drawing methods and require a decent amount of code to manage pixels.
Another option is to use a library or a framework that deals with all that complexity and offer ready-to-use components. And that’s what we’ll do.

The goal of this project is to read serial data from a USB device and display it to a graph using Dear ImGUI.

Serial

Serial is a communication method that sends one bit at a time over a line. A common type is full-duplex UART, where there’s a Transmission line (TX) and a Receiving line (RX) that can exchange data at the same time. In this article series, we connect the ATmega328P to the Linux computer using a Serial-to-USB cable. When we plug the TTL-232R cable into the computer we can read what is sent on the serial line using this command:

We want to read de serial data at the same speed than the cat command. To achieve similar performance we need to use the open() function, a low-level Unix system-call that returns a file descriptor. In linux everything is a file, including the serial port.

Termios

Termios is a header file that helps configure asynchronous communication ports. We set the baud rate to 9600, disable parity checking, select an 8-bit data size, etc. In our project, we use raw input mode to read one byte at a time, contrary to canonical mode, which waits for a full line before returning.

I highly suggest Michael R Sweet’s Serial Programming Guide for a complete dive into the subject:

Data allocation

This section show how the data is initialized and allocated. The buffer member is a CSV-style data structure with rows and columns. It’s designed to hold multiple channels, although in this example we only use one. The xAxisData and yAxisData members are used to store values that will later be used to build the plot line. The other fields (such as head, count, and capacity) help manage the data structure and keep track of its state.

Memory for all buffers is dynamically allocated using malloc().

Reading from serial

The read() function, in this example, reads 64 bytes of data from the serial port. After getting the data, we go through each character one by one and check if it’s not a line return ('\n'). If it’s not, we add it to a temporary line buffer. Once we get a full line, we start the tokenization process. Since we know the format consists of values separated by commas, we can use strtok() to break the string into a sequence of delimited tokens. We copy the first token into the CSV buffer and look for the next one. If there are no tokens left, we exit the loop and advance the head using a circular method.



Dear ImGUI

Dear ImGUI is a popular C++ library for building graphical user interface. It’s used in the game industry because it’s quite complete and use the immediate mode paradigm. One of it’s principal is to have only one source of truth for the data being drawn on the screen. Another one is to throw out and rebuild the UI on every frame rather than having persitent UI widget. Which differ from retained mode that would use long-lived objects that would decribe the UI state over time.
